# SELECT절 사용자 함수 부하 쿼리 튜닝

- **참조 원본**: `raw/clippings/2026-06-02-함수 부하가 병목인 쿼리 튜팅.md`

## 1. 핵심 요약
- SELECT 절의 사용자 정의 함수는 조건절에 부합하는 모든 행에 대해 recursive call을 발생시켜 심각한 성능 병목이 되므로, 인라인 뷰·JOIN·스칼라 서브쿼리 캐싱·DETERMINISTIC 선언 등으로 호출 횟수를 최소화해야 한다.

## 2. 상세 설명

### 문제 유형

```sql
SELECT
    ...
    , JISA_NAME( A.JISA_code ) 지사이름
    ...
FROM 자금지원이력 A
WHERE A.기간 BETWEEN sysdate - 10/24/60 AND sysdate
GROUP BY A.region
```

`JISA_NAME()` 같은 사용자 함수가 SELECT 절에 위치하면 GROUP BY 집계 이전의 **전체 레코드 수**만큼 함수가 호출된다.

### 병목 원인

- 사용자 함수는 내부적으로 **recursive call**로 실행되어 일반 SQL 연산보다 훨씬 느리다.
- 최종 결과가 적어도 조건을 만족하는 **중간 레코드 수** 전체에 대해 호출이 발생한다.

### 튜닝 방법

#### 1) 인라인 뷰로 집계 후 함수 호출 (NO_MERGE 힌트)

```sql
SELECT
    ...
    , JISA_NAME( jisa_code ) 지사이름
FROM (
    SELECT /*+ NO_MERGE */
        A.region
        , A.jisa_code
        ...
    FROM 자금지원이력 A
    WHERE A.기간 BETWEEN sysdate - 10/24/60 AND sysdate
    GROUP BY A.region
)
```

인라인 뷰에서 먼저 GROUP BY 집계를 완료하면 **최종 결과 건수**에만 함수가 호출된다.  
`NO_MERGE` 힌트로 옵티마이저의 인라인 뷰 머지를 방지해야 한다.

#### 2) DECODE / CASE 문으로 대체

함수 로직이 단순 계산식이라면 인라인 SQL 식으로 변환한다.

#### 3) JOIN으로 변환

```sql
SELECT B.JISA_NAME
FROM 자금지원이력 A, 지사이름 B
WHERE A.jisa_code = B.jisa_code
  AND A.기간 BETWEEN sysdate - 10/24/60 AND sysdate
GROUP BY A.region
```

함수 내부에서 참조하는 테이블을 직접 JOIN하여 함수 호출 자체를 제거한다.

#### 4) 스칼라 서브쿼리 캐싱 효과

Oracle에서는 `SELECT 함수명 FROM dual` 형태로 작성하면 동일한 입력값에 대한 결과를 캐싱한다.

```sql
SELECT /*+ NO_MERGE */
    ( SELECT JISA_NAME(A.JISA_code) FROM dual ) 지사이름
    ...
```

- Tibero는 `FROM dual` 없이도 plan에 sub-query caching이 표시되나 실제 캐싱 여부는 불확실하다.
- **함수 결과 종류(카디널리티)가 적을 때** 효과가 크다.

#### 5) DETERMINISTIC 함수 선언 (Oracle)

```sql
CREATE OR REPLACE FUNCTION JISA_NAME( p_jisacode VARCHAR )
    RETURN VARCHAR DETERMINISTIC
...
```

`DETERMINISTIC` 키워드를 명시하면 Oracle이 동일 입력에 대해 결과를 캐싱하여 recursive call 횟수를 줄인다.
