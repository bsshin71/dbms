# xmin과 xmax 개념

- **태그**: #PostgreSQL #MVCC #트랜잭션 #내부구조
- **작성일**: 2026-06-02
- **참조 원본**: `raw/xmin과 xmax 개념.md`

## 1. 핵심 요약
- PostgreSQL MVCC의 핵심 메타데이터로, 모든 행(Tuple)에 숨겨진 `xmin`(삽입 트랜잭션 ID)과 `xmax`(삭제·수정 트랜잭션 ID)를 비교해 각 트랜잭션이 볼 수 있는 데이터 버전을 스스로 판단한다.

## 2. 상세 설명

### 기본 개념: 트랜잭션 ID (TXID)

PostgreSQL은 트랜잭션마다 순차적으로 증가하는 고유 번호(TXID)를 부여한다. `xmin`과 `xmax`는 이 번호를 행 단위로 기록하는 숨겨진 시스템 컬럼이다.

| 컬럼 | 의미 |
|------|------|
| `xmin` | 이 행을 **INSERT**한 트랜잭션 번호 |
| `xmax` | 이 행을 **DELETE 또는 UPDATE**한 트랜잭션 번호 (미삭제 시 0) |

### INSERT / DELETE / UPDATE 동작

**INSERT (트랜잭션 100)**

| 데이터 | xmin | xmax |
|--------|------|------|
| "Hello World" | 100 | 0 |

**DELETE (트랜잭션 101)** — 실제로 지우지 않고 xmax에 표시만 한다.

| 데이터 | xmin | xmax |
|--------|------|------|
| "Hello World" | 100 | **101** |

**UPDATE (트랜잭션 102)** — `[구행 xmax 갱신] + [신행 INSERT]`로 처리된다.

| 행 구분 | 데이터 | xmin | xmax | 상태 |
|---------|--------|------|------|------|
| 기존 행 | "Hello World" | 100 | **102** | 구버전 (삭제됨) |
| 새 행 | "Hi World" | **102** | 0 | 신버전 (유효) |

### 가시성 판단 규칙

각 트랜잭션은 아래 규칙으로 어떤 행을 읽을지 결정한다.

1. `xmin > 내 TXID` → 무시 (내가 시작한 뒤에 생긴 데이터)
2. `xmax > 0` 이고 `xmax ≤ 내 TXID` → 무시 (이미 삭제된 데이터)
3. `xmax = 0` 이거나 `xmax > 내 TXID` → **유효** (아직 살아 있는 데이터)

> "내가 태어나기 전에 만들어졌고, 내가 살아있는 동안에는 아직 삭제되지 않은 데이터만 내 눈에 보인다."

이 덕분에 읽기와 쓰기가 서로를 막지 않는 MVCC가 실현된다.
